03 / Data quality

Trust is an analytical deliverable.

The notebook clips negative data usage to zero and removes IQR outliers. A stronger production workflow preserves raw values, flags anomalies, and reports sensitivity.

20,138 negative-value flags require investigation

Counts are field-level; one customer may have more than one flag

AUDIT

Recommended cleaning contract

  1. 1Preserve the sourceLand every record unchanged in raw_telecom with ingestion metadata.
  2. 2Flag before transformingCreate field-level flags for negative calls, SMS, and data usage.
  3. 3Apply a documented ruleUse NULL, winsorization, or zero only when the business meaning supports it.
  4. 4Run sensitivity analysisCompare KPI and segment rankings before and after treatment.
  5. 5Publish the row impactReport excluded, corrected, and retained row counts on the methodology page.
Notebook review: negative values exist in all three usage fields, not only data_used. Applying IQR deletion sequentially can also alter customer mix and should be justified against a non-destructive flagging approach.
04 / SQL evidence

SQL is the analytical backbone, not a screenshot at the end.

These BigQuery Standard SQL patterns make segmentation, sample-size protection, and prioritization reproducible.

-- Portfolio baseline: the reference for every segment
SELECT
  COUNT(*) AS customers,
  COUNT(DISTINCT customer_id) AS unique_customers,
  SUM(churn) AS churned_customers,
  SAFE_DIVIDE(SUM(churn), COUNT(*)) AS churn_rate
FROM `project.dataset.telecom_clean`;
-- Non-destructive treatment: retain source values and add flags
CREATE OR REPLACE TABLE `project.dataset.telecom_clean` AS
SELECT *,
  calls_made < 0 AS invalid_calls_flag,
  sms_sent < 0 AS invalid_sms_flag,
  data_used < 0 AS invalid_data_flag,
  CASE WHEN calls_made < 0 OR sms_sent < 0 OR data_used < 0
    THEN 'review' ELSE 'valid' END AS data_quality_flag
FROM `project.dataset.raw_telecom`;
WITH portfolio AS (
  SELECT SAFE_DIVIDE(SUM(churn), COUNT(*))*100 AS avg_rate
  FROM `project.dataset.telecom_clean`
), segments AS (
  SELECT telecom_partner, state, COUNT(*) AS customers,
    SUM(churn) AS churned,
    SAFE_DIVIDE(SUM(churn), COUNT(*))*100 AS churn_rate
  FROM `project.dataset.telecom_clean`
  GROUP BY 1, 2 HAVING customers >= 300
)
SELECT s.*, churn_rate - avg_rate AS rate_vs_portfolio,
  churned * (churn_rate - avg_rate) AS priority_signal
FROM segments s CROSS JOIN portfolio
ORDER BY priority_signal DESC;
SELECT
  DATE_TRUNC(date_of_registration, QUARTER) AS registration_cohort,
  COUNT(*) AS customers,
  SUM(churn) AS churned_customers,
  SAFE_DIVIDE(SUM(churn), COUNT(*))*100 AS churn_rate
FROM `project.dataset.telecom_clean`
GROUP BY registration_cohort
ORDER BY registration_cohort;
05 / Recommended actions

Move from broad campaigns to measurable, prioritized interventions.

Each recommendation follows finding → implication → action → measurement.

ACTION 01HIGH

Target high-volume, above-baseline intersections

Use the partner × state priority matrix to select the first test cells rather than applying a national retention discount.

MEASURE → incremental retained customers, offer cost, churn lift vs holdout
ACTION 02HIGH

Investigate anomalous usage before scoring risk

Trace negative usage to source-system logic. Until resolved, add missingness/quality indicators and compare model performance with and without affected rows.

MEASURE → invalid-rate trend, corrected records, KPI sensitivity
ACTION 03TEST

Design behavior-led retention experiments

Test service-quality review, usage-adoption nudges, and targeted offers within priority segments using randomized holdouts.

MEASURE → 30/60/90-day retention, uplift, cost per saved customer
06 / Limits & next step

Association is not causation.

This dataset can identify where churn concentrates. It cannot prove why customers left or what intervention will retain them without additional evidence.

BigQueryStandard SQLPythonpandasPlotlyLooker Studio
No causal design: partner, state, age, and usage are associations—not proven churn causes.
Questionable usage: negative values can bias segment statistics and model coefficients.
Outcome timing: registration cohort is not a substitute for observed tenure-to-churn.
Next step: instrument churn reasons, service quality, plan details, and retention experiments.
